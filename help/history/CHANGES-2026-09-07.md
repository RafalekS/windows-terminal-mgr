# Changes — 2026-09-07 (v1.1.0)

Two things happened in one commit: (1) the code was split into modules, and
(2) the Windows Terminal action list + a couple of profile dropdowns were
brought up to date. **No tab was intentionally redesigned.** If something in the
UI behaves differently from before this commit, it is a bug — tell me.

---

## A. Structural (no behaviour change intended)

| Before | After |
|---|---|
| One file `wt_manager.pyw` (~5200 lines) | `wt_manager.pyw` = launcher only; all logic in `modules/` |
| One class `Ui_MainWindow` | Same class, assembled from 6 tab "mixin" files |
| Globals `data_schemes`, `APP_CONFIG`, … | Same values, now `modules.app_state.data_schemes` etc. |

`start.cmd` and how you run it are unchanged: `python wt_manager.pyw`.

### Dead / duplicate code removed (not reachable from the UI)

- `findActualEntry()` — old folder-lookup helper, already replaced by
  `findParentList()` in an earlier release; nothing called it.
- `actionsListWidget` — an invisible list widget kept "for compatibility";
  nothing read it.
- `_main_window` attribute, some unused imports.
- `reselectItemByEntry()` — only ever forwarded to `reselectItemByIdentity()`.
- Six copies of the same profile-field-write block and three copies of the same
  folder "add entry" block were merged into one helper each. Same inputs, same
  outputs.

If any of the above changed behaviour, that is a bug.

## B. Behaviour changes you SHOULD see (deliberate)

### 1. Profiles tab → **Bell Style** dropdown

- **Before:** `audible`, `none`, `visual`, `all`
- **After:** `all`, `audible`, `window`, `taskbar`, `none`
- **Why:** `"visual"` is not a value Windows Terminal accepts. The real options
  are `window` (flash the window) and `taskbar` (flash the taskbar icon). See
  https://learn.microsoft.com/en-us/windows/terminal/customize-settings/profile-advanced#bell-notification-style
- **On load:** if your `settings.json` has `"bellStyle": "visual"` it is shown
  as `window`. A list like `["audible","window"]` is shown as the single
  closest item (this is lossy — see TODO).

### 2. Profiles tab → **Close on Exit** dropdown

- **Before:** `graceful`, `always`, `never`
- **After:** `automatic`, `graceful`, `always`, `never`
- **Why:** `automatic` is the current WT default (added when WT became the
  default terminal). Same docs page, "Profile termination behavior".

### 3. Actions & Key Bindings tab → **Built-in Action** dropdown

- **Before:** ~40 names, 3 of them wrong:
  - `duplicatePane` — not a real action (it's `splitPane` with
    `"splitMode": "duplicate"`)
  - `toggleSplitOrientation` — removed from WT
  - `commandPalette` — replaced by `showSuggestions`
- **After:** the full current list (~70 names) from
  https://learn.microsoft.com/en-us/windows/terminal/customize-settings/actions ,
  grouped (Application / Tab / Window / Pane / Clipboard / Scrollback / Visual /
  Marks / Other). The box is still editable, so you can still type anything.

Nothing else in the Actions tab changed. New-tab / split-pane / send-input /
pane-direction editors, the key recorder, add/update/delete/move, unbound-key
handling — all identical.

## C. What did NOT change

- **Folders & New Tab Menu tab** — identical. The right-hand panel enables only
  the fields relevant to the selected item type (folder → Folder Name/Icon/Allow
  Empty/Inline; profile entry → Profile + Profile Icon; separator → nothing).
  That is the pre-existing design, not new. (It is confusing and on the TODO to
  redesign — but it is not a regression.)
- Command Builder tab — identical (builder, parser, copy/run).
- Settings tab — identical.
- Fragment Extensions tab — identical.
- Profiles tab, every field other than the two dropdowns above — identical.
- `dumpJson()` / backups / `_wt_uid` stripping — identical.
